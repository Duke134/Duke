- 전제: 클라우드 세션은 GitHub 저장소 안에서 코드·문서를 만들고 테스트하는 작업에 강하고, 옵시디언·로컬 파일·회사 시스템에는 닿지 않는다. 실제 데이터 대신 샘플 데이터로 만들고, 실데이터는 Duke PC에서만 돌린다.

3. 개인정보·회사 정보가 저장소에 올라가지 않는가
4. 결과가 눈에 보이는가 (웹페이지·엑셀·스크립트)

## 추천 실행안 (9일)

크레딧은 세션 수가 아니라 작업량으로 줄어드니, 큰 과제 2개 + 작은 과제 3개 정도가 적당하다.

| 순서 | 과제 | 이유 |
|---|---|---|
| 1 | **A2 일정 캘린더 생성기** | 가장 작고 바로 쓰임. 결과(.ics)를 캘린더에 넣으면 끝 |
| 2 | **A1 대사 도구** | 월마감에 직접 효과. 11월 마감 전에 완성 가능 |
| 3 | **B2 볼트 점검 스크립트** | 옵시디언 운영 규칙(Inbox 48시간)을 자동 점검 |
| 4 | **B1 계산기 페이지** (퇴직금·연차부터) | 사이트·블로그·실무 셋 다 연결 |
| 5 | **B3 블로그 샘플 글** | 남는 크레딧으로. 구조 검증용 |

C 항목은 크레딧이 남으면 C3(디데이 보드)부터.

## 공통 규칙
- 실제 급여·계좌·거래처 데이터는 저장소에 올리지 않는다. 개발은 샘플 데이터로, 실행은 Duke PC에서.
- 법정 기한·요율·계산식은 조문을 대조하고, 못 한 것은 `(조문 미확인)` 또는 `[확인 필요]`로 표시한다.
- 과제마다 `README`(사용법 5줄)와 샘플 입력·출력 파일을 함께 둔다.
- 완성 후 PR을 만들어 Duke가 보고 Merge한다.

## 참고
- 클라우드 세션은 PR 생성 흐름에 맞춰져 있고, 로컬에 없는 저장소를 다룰 때 유용하다 (support.claude.com, daleseo.com).
- 개인 프로젝트는 "내 파일을 다루는 작은 도구"부터 시작하고 처음부터 로그인·결제·DB는 넣지 말라는 조언이 많다 (codelikeagirl.substack.com, claudecode-lab.com).
- 경영지원 실무에서는 은행 CSV 변환, 일일 자금현황, 비품 관리가 자동화 후보로 자주 언급된다 (wikidocs.net, comento.kr).
