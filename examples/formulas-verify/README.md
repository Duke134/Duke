# formulas로 엑셀 없이 시트 재검산하기

`formulas`(vinci1it2000) 라이브러리로 엑셀 워크북을 Excel 없이 재계산하고, 구조 점검과 독립 재계산을 거쳐
`✅ 검증완료` 여부를 판정합니다. 숫자는 전부 가상 샘플입니다.

```bash
pip install -r requirements.txt      # Python 3.13 기준. formulas[excel] 추가 옵션은 ezodf 빌드 실패로 제외
```

| 파일 | 역할 |
|---|---|
| `make_runway.py` | 런웨이 워크북 생성 (빈 템플릿 / `--example` 예시본) |
| `verify.py` | **런웨이 워크북 재검산** (아래 레이아웃 전용) |
| `make_sample.py`, `verify_sample.py` | 처음 만든 작은 데모(런웨이 12개월·급여 3명). formulas 동작 확인용 |

## verify.py (런웨이 워크북)

```bash
python verify.py runway_example.xlsx                          # ✅ 검증완료, exit 0
python verify.py runway_template.xlsx                         # ❌ 입력·원자료 미기재 안내, exit 1
python verify.py runway_example.xlsx --set "입력!B6=900000000" # 기초현금 시나리오
```

| 단계 | 내용 |
|---|---|
| 입력·원자료 검사 | 기준월·기초현금 필수, 구분·주기·통화·확정 값이 목록에 있는지, 금액 양수, 종료월 ≥ 시작월, USD 줄이 있으면 환율 기재 |
| 수식 구조 검사 | 월별현금흐름 모든 행, 전개표 모든 줄·보조열이 첫 셀 수식의 평행이동인지(openpyxl `Translator`). 요약·보고에 손으로 친 숫자 없음. 재계산 오류 셀 없음 |
| 독립 전개 대조 | 원자료를 파이썬으로 직접 월별 전개 → 구분별 합계·순현금흐름·보수적·기말현금 18개월, 요약(런웨이·보수적·안전선·최저·소진월·미달월) 대조. 허용오차 ±0.5원 |
| Excel 저장값 대조 | Excel이 저장한 파일이면 저장값 vs 재계산값 (수동 계산 모드·저장 후 수정 탐지) |

입력·원자료 오류가 있으면 독립 전개 대조는 "생략"으로 표시하고 ✅를 붙이지 않습니다.

실수 5개를 심은 사본으로 확인: 월별현금흐름 셀 하드코딩, 전개표 중간 줄 수식 훼손, 요약에 숫자 직접 입력,
원자료 주기 오타("매달"), 종료월이 시작월보다 앞 → 전부 적발.

## 만들면서 확인한 점

- **부동소수점 절사 주의**: 3,600,000 × 0.9% = 32,399.999999999996으로 계산되는데 Excel과 formulas는 15자리 유효숫자로 정리해 32,400으로 절사합니다. 순수 파이썬 `int()` 절사는 10원씩 틀립니다. 독립 재계산의 ROUNDDOWN은 `float(f"{x:.15g}")` 후 절사로 맞춰야 합니다.
- **구조 검사가 설계 흠도 잡음**: "런웨이 계산 포함" 행이 열마다 다른 상수(1,2,3…)를 수식에 박아 넣고 있던 것을 평행이동 검사가 잡아내서, 월 번호 행을 참조하도록 생성기를 고쳤습니다.
- **한글 시트명·파일명**은 formulas에서 문제없이 동작합니다. 결과 키는 `'[파일명.xlsx]시트명'!A1` 형태.

# GXC 런웨이 시트 (`make_runway.py`)

```bash
python make_runway.py            # runway_template.xlsx  빈 템플릿
python make_runway.py --example  # runway_example.xlsx   가상 원자료를 채운 예시본
```

노란 칸(입력·원자료)만 채우면 나머지는 전부 수식입니다. 글꼴 맑은 고딕, 모든 시트 가로 A4 폭 맞춤 인쇄.

## 시트 구성과 데이터 흐름

```
입력 ─┐
원자료_유출 ─┬→ 전개표(줄×18개월 자동 전개) → 월별현금흐름(구분별 SUMIFS) → 요약 → 보고
원자료_유입 ─┘
```

| 시트 | 역할 |
|---|---|
| 보고 | 첫 탭. 헤드라인 4개(런웨이, 보수적 런웨이, 소진 예상월, 최저 잔액) + 보고 문구 + 차트 2개. 한 장 인쇄 |
| 입력 | 기준월, 기초현금, 비용 시나리오율(10%), 런웨이 기준 개월수(6), USD 환율, 안전 잔액 기준 개월수(3) |
| 원자료_유출 | 비용 목록. 열 9개: 구분(8종 드롭다운) / 항목 / 금액(1회분) / 통화(KRW·USD) / 주기(매월·분기·반기·연·1회) / 시작월 / 종료월 / 확정·예정 / 메모·근거. 급여는 급여대장 총액 한 줄 |
| 원자료_유입 | 수입 목록. 구분 4종(매출·정부지원금·투자금·이자기타), 열은 유출과 동일 |
| 전개표 | 원자료 각 줄을 18개월로 펼친 검산용. 주기·시작·종료월을 보고 해당 월에만 금액이 찍힘. 손대지 않음 |
| 월별현금흐름 | 전개표를 구분별로 SUMIFS. B열은 원자료 건수. 손으로 치는 숫자 없음 |
| 요약 | 런웨이(확정+예정), 보수적 런웨이(확정 유입만), 소진 예상월, 최저 잔액, 비용 시나리오 |

## 계산 규칙

- **런웨이** = 기초현금 ÷ |기준월부터 N개월 평균 순소진|. 투자금 입금은 제외(잔액 추이에는 반영).
- **보수적 런웨이** = 유입은 '확정'만, 유출은 확정+예정 전부, 투자금 제외. 예정 매출·지원금이 안 들어올 때의 값.
- **주기 전개**: 시작월부터 주기 간격(매월 1, 분기 3, 반기 6, 연 12)으로 반복, 종료월이 있으면 그달까지. '1회'는 시작월에만.
- **USD**: 원자료 통화가 USD인 줄은 입력!B9 환율로 원화 환산.
- **안전 잔액선** = 향후 N개월 평균 월 유출 × 안전 기준 개월수(입력!B10, 기본 3). 월별현금흐름에 행으로, 보고 차트에 주황 점선으로 표시되고 요약에 "안전선 미달 예상월"이 나옴.
- 입금·출금 기준(발생 기준 아님).

## 검증

예시본을 formulas 1.3.4로 재계산하고 파이썬 독립 전개와 대조해 요약 8개 값, 월별현금흐름 5개 행 × 18개월이 전부 일치했습니다. 오류 셀 없음. LibreOffice로 PDF 렌더링해 보고·원자료·전개표 레이아웃을 확인했습니다.

formulas 호환을 위해 피한 것: `OFFSET`(미지원), `TEXT`의 부호 섹션 서식(`+0;-0`, 결과가 틀림). 대신 포함 플래그 행 + `SUMPRODUCT`, `IF(x>=0,"+","")`를 씁니다. `SUMIFS`, `COUNTIF`, `EDATE`, `MOD`, `INDEX/MATCH`, `IFERROR`는 정상 동작.

## 실제 적용 순서

1. 입력 시트: 기준월, 기초현금(계좌 합계), USD 환율
2. 원자료_유출: 급여대장 총액 2줄(실지급, 4대보험·원천세), 임대차·외주·SaaS·송금·세금 순으로 계약서 보며 한 줄씩
3. 원자료_유입: 확정 입금부터, 예정 건은 '예정'으로
4. 전개표에서 분기·연 항목이 맞는 달에 찍혔는지 훑기
5. 보고 시트 인쇄 또는 보고 문구 복사
