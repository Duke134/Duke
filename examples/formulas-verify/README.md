# formulas로 엑셀 없이 시트 재검산하기

`formulas`(vinci1it2000) 라이브러리로 런웨이·급여 워크북을 Excel 없이 재계산하고,
구조 점검과 독립 재계산을 거쳐 `✅ 검증완료` 여부를 판정하는 예시입니다.
숫자는 전부 가상 샘플입니다.

## 실행

```bash
pip install -r requirements.txt      # Python 3.13 기준. formulas[excel] 추가 옵션은 ezodf 빌드 실패로 제외
python make_sample.py                # sample_clean.xlsx, sample_broken.xlsx 생성
python verify.py sample_clean.xlsx   # ✅ 검증완료, exit 0
python verify.py sample_broken.xlsx  # ❌ 오류 3건 적발, exit 1
python verify.py sample_clean.xlsx --set "입력!B4=93500000"   # 인건비 +10% 시나리오
```

## verify.py가 하는 일

1. **재계산**: `ExcelModel().loads(path).finish().calculate()`로 전체 수식을 Excel 없이 계산
2. **구조 점검**: openpyxl `Translator`로 첫 행 수식을 아래 행에 투영해 비교
   - 수식 열에 값이 하드코딩된 셀
   - 행 간 수식 패턴 불일치 (잘못된 행 참조)
   - 합계 SUM 범위가 데이터 행을 빠뜨린 경우
3. **독립 재계산**: 입력 셀(노란색)만 읽어 파이썬으로 다시 계산한 뒤 시트 결과와 대조 (허용오차 ±0.5원)
4. **보고**: 결과 / 계산과정 / 근거 / 주의사항 4필드 + `✅ 검증완료` 또는 `❌ 검증 실패`
5. **시나리오**: `--set 시트!셀=값`으로 입력을 덮어써 what-if 결과를 바로 확인

## sample_broken.xlsx에 심은 실수 3개와 적발 결과

| 위치 | 실수 | 적발 방식 |
|---|---|---|
| 런웨이!H7 | 수식 자리에 996,000,000 하드코딩 | 구조 점검 (하드코딩) + 기말현금 불일치 |
| 런웨이!C9 | 성장률 수식이 C8 대신 C7 참조 | 구조 점검 (수식 불일치) |
| 급여!B6 | 합계가 SUM(B2:B3), 마지막 직원 누락 | 구조 점검 (SUM 범위) + 합계 불일치 |

## 만들면서 확인한 점

- **부동소수점 절사 주의**: 3,600,000 × 0.9% = 32,399.999999999996으로 계산되는데,
  Excel과 formulas는 15자리 유효숫자로 정리해 32,400으로 절사합니다.
  순수 파이썬 `int()` 절사는 32,390을 내놓아 10원씩 틀립니다. 독립 재계산에서 ROUNDDOWN을
  Excel 방식(`float(f"{x:.15g}")` 후 절사)으로 맞춰야 거짓 불일치가 안 납니다.
- **Excel 저장값 대조**: Excel이 저장한 파일은 캐시값이 있어 "저장값 vs 재계산" 대조로
  수동 계산 모드·저장 후 입력 변경을 잡을 수 있습니다. openpyxl이 만든 파일엔 캐시값이 없어 이 단계는 건너뜁니다.
- **한글 시트명·파일명**: formulas 결과 키는 `'[파일명.xlsx]시트명'!A1` 형태이며 한글 시트명도 문제없이 동작했습니다.
- **구조 점검은 레이아웃 의존**: 어느 열이 수식 열이고 어느 행이 데이터 행인지는 템플릿별로 알려줘야 합니다.
  실제 급여·런웨이 시트에 붙일 때는 `structural_checks()`의 범위만 해당 시트 레이아웃으로 바꾸면 됩니다.

## 실무 적용 아이디어

- 월 급여대장 확정 전 클라우드 세션에서 `verify.py` 실행 → exit 0일 때만 `✅ 검증완료` 표기
- 런웨이 시트에 `--set`으로 채용·임차료 변경 시나리오를 돌려 대표님 보고용 숫자 근거 블록 생성
- excel-session 스킬에 "formulas로 재계산 후 독립 계산과 대조" 절차를 추가

# GXC 런웨이 시트 (`make_runway.py`)

```bash
python make_runway.py            # runway_template.xlsx  빈 템플릿
python make_runway.py --example  # runway_example.xlsx   가상 원자료를 채운 예시본
```

노란 칸(입력·원자료)만 채우면 나머지는 전부 수식입니다. 글꼴 맑은 고딕, 모든 시트 가로 A4 폭 맞춤 인쇄.

## 시트 구성과 데이터 흐름

```
입력 ─┐
원자료_유출 ─┬→ 전개표(줄×18개월 자동 전개) → 월별현금흐름(구분별 SUMIFS) → 요약 → 보고
원자료_유입 ─┘
```

| 시트 | 역할 |
|---|---|
| 보고 | 첫 탭. 헤드라인 4개(런웨이, 보수적 런웨이, 소진 예상월, 최저 잔액) + 보고 문구 + 차트 2개. 한 장 인쇄 |
| 입력 | 기준월, 기초현금, 비용 시나리오율(10%), 런웨이 기준 개월수(6), USD 환율 |
| 원자료_유출 | 비용 목록. 열 9개: 구분(8종 드롭다운) / 항목 / 금액(1회분) / 통화(KRW·USD) / 주기(매월·분기·반기·연·1회) / 시작월 / 종료월 / 확정·예정 / 메모·근거. 급여는 급여대장 총액 한 줄 |
| 원자료_유입 | 수입 목록. 구분 4종(매출·정부지원금·투자금·이자기타), 열은 유출과 동일 |
| 전개표 | 원자료 각 줄을 18개월로 펼친 검산용. 주기·시작·종료월을 보고 해당 월에만 금액이 찍힘. 손대지 않음 |
| 월별현금흐름 | 전개표를 구분별로 SUMIFS. B열은 원자료 건수. 손으로 치는 숫자 없음 |
| 요약 | 런웨이(확정+예정), 보수적 런웨이(확정 유입만), 소진 예상월, 최저 잔액, 비용 시나리오 |

## 계산 규칙

- **런웨이** = 기초현금 ÷ |기준월부터 N개월 평균 순소진|. 투자금 입금은 제외(잔액 추이에는 반영).
- **보수적 런웨이** = 유입은 '확정'만, 유출은 확정+예정 전부, 투자금 제외. 예정 매출·지원금이 안 들어올 때의 값.
- **주기 전개**: 시작월부터 주기 간격(매월 1, 분기 3, 반기 6, 연 12)으로 반복, 종료월이 있으면 그달까지. '1회'는 시작월에만.
- **USD**: 원자료 통화가 USD인 줄은 입력!B9 환율로 원화 환산.
- 입금·출금 기준(발생 기준 아님).

## 검증

예시본을 formulas 1.3.4로 재계산하고 파이썬 독립 전개와 대조해 요약 8개 값, 월별현금흐름 5개 행 × 18개월이 전부 일치했습니다. 오류 셀 없음. LibreOffice로 PDF 렌더링해 보고·원자료·전개표 레이아웃을 확인했습니다.

formulas 호환을 위해 피한 것: `OFFSET`(미지원), `TEXT`의 부호 섹션 서식(`+0;-0`, 결과가 틀림). 대신 포함 플래그 행 + `SUMPRODUCT`, `IF(x>=0,"+","")`를 씁니다. `SUMIFS`, `COUNTIF`, `EDATE`, `MOD`, `INDEX/MATCH`, `IFERROR`는 정상 동작.

## 실제 적용 순서

1. 입력 시트: 기준월, 기초현금(계좌 합계), USD 환율
2. 원자료_유출: 급여대장 총액 2줄(실지급, 4대보험·원천세), 임대차·외주·SaaS·송금·세금 순으로 계약서 보며 한 줄씩
3. 원자료_유입: 확정 입금부터, 예정 건은 '예정'으로
4. 전개표에서 분기·연 항목이 맞는 달에 찍혔는지 훑기
5. 보고 시트 인쇄 또는 보고 문구 복사
